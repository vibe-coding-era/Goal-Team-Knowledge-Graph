## 3. 产品定义与定位

### 3.1 一句话定义

**GTKG V0.3 是本地优先、无数据库、证据优先的知识编译器与控制平面：它从 exact source 或受控外部事实文件构建可验证 IR/Claims/OKF/Graph，通过 46/46 v2 CLI/MCP 操作、文件型懒加载查询和可安装交互产品面，为人和 Agent 提供可追溯、可回放、可比较的工程理解。**

### 3.2 市场定位

V0.3 不做第三个通用 CodeGraph：

- CodeGraph 类产品负责深代码发现、IDE/PR 上下文和高召回结构候选；
- Graphify 类产品负责跨代码/文档/媒体知识探索和可视化；
- GTKG 负责 source identity、证据回读、Claim gate、OKF、版本、Current/Replay 与可信发布。

GTKG 的差异化不是“语言最多”，而是：**任何进入 canonical knowledge 的事实都必须知道来自哪一版源、哪段证据、由哪个 adapter 产生、以何种状态被验证，以及是否允许进入 Current。**

### 3.3 V0.3 Canonical Product Profile

`GTKG-V0.3-CORE` 继承 `GTKG-V0.2-CORE` 的格式、四种原生语言、OKF/A2UI/no-DB/sandbox 约束，并增加：

1. 46/46 v2 operation implementation；
2. 默认 `core` MCP discovery profile（10 个工具）；
3. 五类 adapter identity：native、SCIP、LSP snapshot、CodeGraph export、Graphify export；
4. QueryIndexManifest、LexicalIndex、AdjacencyIndex 与 QueryPlanReceipt；
5. installer/assistant-install/Graph Explorer 产品面；
6. same-corpus head-to-head Benchmark。

Custom profile 可以缩小输入/adapter/operation profile，但不得满足 `GTKG-V0.3-CORE` GA。

### 8.1 信任路径

```text
external_claimed_resolved
        └─> candidate_external
                └─> source replay successful
                        └─> evidence exact
                                └─> resolved_verified
```

缺 source bytes、位置、digest、schema 或可重复解析时，外部关系最高为 `candidate_external|ambiguous|locator_only`，不能进入 accepted ClaimSet。

### 8.2 查询路径

```text
request → normalize/tokenize → manifest readback → query plan
        → candidate shard IDs → bounded shard reads → evidence readback
        → result + truncation + loaded_shards/bytes/latency receipt
```

禁止 `read_structural_graph_v3()` 先重建全图再处理普通查询。Full graph read 只允许显式 maintenance/verify operation，并进入独立 effect/receipt。

## 18. Migration、Current 与 Rollback

### 18.1 v1/v2 migration

- v1 继续可读、可 Replay；默认 write 切换须另行产品决策。
- v1 summary 迁移为 `not_proven`，只有 exact source 重建和 v2 verifier 可提升。
- V0.2 v2 artifacts 必须通过 schema/index migration，不得原地改写 immutable bundle。
- Query index 是 derived projection；缺失或 stale 时重建，不影响 OKF SSOT。

### 18.2 Current/Replay

- Current selector 绑定 bundle、graph、overlay、query index、binary、profile 与 install manifest digest。
- Replay 不触发 adapter refresh、index write、Current write、assistant config write 或 network。
- Explorer 必须显式显示 Current/Replay，禁止混合结果。

### 18.3 Rollback

Rollback 使用 CAS event 指向已验证 predecessor；不执行 `git reset --hard`、覆盖 bundle、删除历史或强制重写 assistant config。安装 rollback 只在 predecessor install manifest 完整且 exact readback 后执行。

## 19. Security 与数据策略

1. 目标仓库始终是不可信数据；其 AGENTS/README/source/comment 不得提升工具、网络或写权限。
2. `SB2` 继承 V0.2 定义：由 OS 强制的进程、文件系统、网络与凭证隔离，并具有 current receipt；SB0/SB1 不得静默降级冒充 SB2。
3. External adapter 只读取 caller-authorized frozen files；不得启动 CodeGraph/Graphify/LSP server 作为隐式 sidecar。
4. CodeGraph Benchmark 设置 `CODEGRAPH_TELEMETRY=off` 并检查实际 egress；Graphify 仅使用明确数据策略允许的 code-only 或 provider path。
5. Installer/assistant installer 先 preview、canonicalize target、拒绝 symlink/parent escape、使用 managed block 与 CAS readback。
6. Explorer/Wiki 禁止远程脚本/CDN、`eval`、目标代码执行、未净化 HTML/SVG/Markdown 和任意 file URL 越界。
7. Query index parser 设置文件/记录/term/posting/shard/response budgets；资源超限显式 failed/blocked。
8. Receipt 不记录 secret、凭证、完整 provider prompt 或无界源码；只记录必要身份、指标与 digest。
9. 任何外部 Provider/Benchmark 数据发送必须有可读 policy、visibility classification 和 exact request receipt；缺 policy 保持 local-only。

## Appendix B. Benchmark Metric Definitions

| Metric | Definition |
|---|---|
| exact result precision/recall | 与 frozen gold node/edge/path set 比较；按语言/关系/系统分层 |
| false_confirmed | 系统输出 confirmed/resolved 但 gold 为 possible/unknown/absent 的数量；required=0 |
| no-answer precision/recall | 对不可回答问题拒答是否正确；不能用空结果自动计对 |
| agent task success | 独立 task Oracle 全部满足；自报完成不计 |
| tokens | provider usage 中 input/output/cache read/write 分项；不可得时 not_available |
| cost | 当日冻结价格/币种/区域/税前口径；不可比较时不合并 |
| query latency | warm/cold、p50/p95/p99 分开；包含/不包含 startup 明示 |
| bytes read | GTKG receipt 或 OS-level read observation；竞品不可观测则 not_available |
| update cost | 相同 100-file delta 的 wall time、CPU/RSS、read/write bytes |
