# 文档知识图谱

文档知识图谱让分散在不同文档中的概念、事实、观点、决策和证据彼此建立联系，使知识不再只是“被保存的内容”，而成为可以被理解、追溯、组合和持续复用的组织记忆。

## 一句话定义

文档知识图谱是一种以文档为知识载体、以关系为组织方式、以来源和版本为可信依据的知识表达方法。

## 标准文案

传统文档擅长承载内容，却不擅长表达内容之间的联系。随着资料不断增加，同一个概念可能出现在多份文档中，同一个结论可能经历多次修订，不同团队也可能对同一术语形成不同理解。人们能够找到文档，却未必能够快速判断哪一份更相关、哪一个结论更新、某项观点依据什么，以及它会影响哪些后续知识。

文档知识图谱把文档中的关键知识识别为可连接的知识对象，并明确它们之间的支持、引用、依赖、演化、冲突和关联关系。每项知识保留自己的语境、来源和版本，使使用者不仅能看到“答案是什么”，还能理解“答案来自哪里、为什么成立、在什么条件下适用”。

它的价值不在于取代文档，而在于让文档之间形成知识网络。原始表达仍然留在文档中，知识图谱负责建立跨文档的连接与线索。这样既保留了完整上下文，也让检索、问答、学习、决策和内容复用获得更可靠的知识基础。

## 核心价值

### 提升知识复用

将可复用的概念、结论、方法和经验从单篇文档的上下文中识别出来，并通过关系连接到相关主题和使用场景。新任务可以从已有知识出发，而不是重复阅读、整理和推导。

### 提升检索质量

检索不再只依赖标题或关键词，还可以沿着概念、来源、主题、时间、版本和关系查找。使用者可以从一个知识点继续追踪其证据、前置条件、相关决策和后续影响。

### 减少歧义

同名概念、不同口径和不同时间形成的结论被明确区分。知识的含义由上下文、定义、来源和关系共同说明，避免把“看起来相似”误判为“完全相同”。

### 增强可信度

重要结论与其来源、证据和修订过程保持关联。无法确认、存在争议或已经过时的内容仍可被记录，但会保留相应状态，避免与已确认事实混为一谈。

### 延续组织记忆

人员、项目和阶段会变化，知识图谱保留知识之间的来龙去脉。后来的使用者可以理解一项决策如何形成、哪些条件已经改变，以及哪些经验仍然适用。

## 基本知识对象

| 知识对象 | 含义 | 典型示例 |
|---|---|---|
| 概念 | 对术语、主题或对象的稳定说明 | 客户价值、风险等级、服务标准 |
| 主张 | 可以被支持、质疑或修订的陈述 | 某方法能缩短交付周期 |
| 事实 | 在给定来源与时间范围内可核验的信息 | 调研样本数量、政策发布日期 |
| 证据 | 支持或反驳某项主张的材料 | 调研记录、会议纪要、公开报告 |
| 决策 | 在特定背景下形成的选择及理由 | 采用某种策略并说明取舍 |
| 方法 | 可重复使用的步骤、原则或实践 | 评审流程、研究方法、检查清单 |
| 版本 | 同一知识在时间上的修订与演化 | 初始定义、修订结论、现行口径 |
| 语境 | 知识成立或适用的条件 | 地区、时间、对象、业务阶段 |

## 关键关系

文档知识图谱通过关系表达知识之间的意义，而不是简单地把内容堆在一起。常见关系包括：

- 来源于：说明知识从何处获得或演化而来。
- 支持：说明证据或事实如何增强某项主张的可信度。
- 反驳：说明某项知识与另一项主张不一致的依据。
- 依赖于：说明理解或使用当前知识所需的前置知识。
- 替代：说明新版本在什么范围内取代旧版本。
- 影响：说明一项决策、条件或变化会作用于哪些知识。
- 相关于：说明存在联系，但暂不宣称更强的因果或等价关系。
- 冲突于：保留不同来源、口径或观点之间尚未消解的矛盾。

关系本身也应保留出处和语境。没有充分依据时，只记录“可能相关”或“待确认”，不把推测升级为事实。

## 知识形成过程

1. 从文档中识别值得长期保存和复用的知识。
2. 区分概念、事实、主张、证据、决策和方法。
3. 为知识补充来源、时间、版本与适用语境。
4. 建立知识之间可解释的关系。
5. 记录冲突、缺口、不确定性和待确认事项。
6. 在检索、问答、研究和决策中复用知识。
7. 随新材料出现而修订，不覆盖历史来路。

## 技术指导

本节给出平台无关的知识建模指导。它描述“知识应如何被表达和使用”，不限定具体软件、存储方式或供应商。

### 1. 先确定建模边界

建模对象应服务于明确的知识消费者，例如研究人员、内容团队、决策者、新成员或智能助手。不要因为某段文字可以被拆分，就默认它值得成为独立知识对象。

建议采用以下准入标准：

- 能被跨文档引用、复用或验证。
- 具有相对明确的语义和适用范围。
- 能关联到来源、责任主体或形成时间。
- 对检索、判断、决策或学习具有实际价值。

过细会产生大量缺乏意义的碎片，过粗则无法建立精确关系。一般以“脱离原段落后仍可被解释，但必须保留来源语境”为合适粒度。

### 2. 分离稳定身份与具体版本

同一知识对象应有稳定身份，用于跨文档、跨时间保持连续性；每次修订则应形成独立版本，用于记录当时的内容、来源和状态。

- 稳定身份回答“这是什么知识”。
- 版本身份回答“这次具体表达是什么”。
- 文档位置回答“它出现在哪里”。

标题、文件名、章节编号和行号可能变化，不宜单独作为长期身份。别名只表示不同称呼，不自动意味着两个对象完全等价；只有经过明确核实，才能合并身份。

### 3. 把主张、证据和来源分开

主张是可以被支持、反驳或修订的陈述；证据是用于评价主张的材料；来源则说明材料或主张来自哪里。三者不应混为一体。

每项重要主张至少应回答：

1. 主张的准确文本是什么？
2. 它在什么语境和时间范围内成立？
3. 哪些材料支持或反驳它？
4. 证据是原始来源、转述来源还是分析结果？
5. 当前状态是已记录、已核验、存在争议、待确认还是已失效？

“被引用”不等于“被证实”。来源数量也不等于证据强度；多个材料可能来自同一原始信息，不能被误判为相互独立的证据。

### 4. 使用明确且克制的关系

关系应使用受控词汇，并为方向、含义和适用条件提供定义。每条关系应能被人解释，必要时也应关联来源或依据。

关系设计应遵循：

- 区分方向，例如“甲依赖乙”不同于“乙依赖甲”。
- 区分强弱，例如“相关”不能替代“导致”。
- 区分事实与描述：文档提到一个关系，不代表该关系已经被确认。
- 避免无依据的传递：甲相关乙、乙相关丙，不能自动推出甲相关丙。
- 关系发生实质变化时保留旧记录，并说明替代或修订原因。

建议将模糊的“相关于”作为最后选择。能够明确为“支持、反驳、依赖、替代、影响或来源于”时，应优先使用更具体的关系。

### 5. 显式表达不确定性

知识状态建议至少区分：

| 状态 | 含义 | 使用建议 |
|---|---|---|
| 已记录 | 文档中存在该内容，但尚未独立核验 | 可检索，不直接作为确定结论 |
| 已核验 | 来源与语境已经检查 | 可用于受控回答与决策参考 |
| 推断 | 根据已有知识推导，原文未直接陈述 | 必须说明推断链 |
| 有争议 | 存在相互冲突的来源或解释 | 同时呈现主要观点与证据 |
| 待确认 | 信息不足或身份尚未解析 | 不参与确定性结论 |
| 已失效 | 曾经有效，但已被更新或不再适用 | 默认不作为现行答案 |

置信度可以辅助排序，但不能代替知识状态、证据质量和适用语境。一个高置信度推断仍然是推断，不应被呈现为原始事实。

### 6. 让检索返回“答案包”

专业检索不应只返回一个文本片段。建议把结果组织为答案包，至少包括：

- 匹配到的知识对象与当前版本。
- 原始来源和精确上下文。
- 支持、反驳或限制该结论的证据。
- 相关概念、前置条件和后续影响。
- 是否存在同名对象、多个版本或冲突解释。
- 本次结果的未知项与适用边界。

检索流程可分为“候选召回—语义筛选—证据排序—歧义处理—结果解释”五步。关键词适合发现候选，关系适合扩展上下文，来源和版本适合判断可信度；任何单一信号都不应独立决定最终答案。

### 7. 建立可观察的质量规则

建议持续观察以下问题：

- 稳定身份重复或不同对象发生身份碰撞。
- 同一主张存在互相冲突的现行版本。
- 关系指向不存在或无法解析的对象。
- 重要主张缺少来源、证据或适用语境。
- 别名被错误当作完全等价关系。
- 已失效知识仍被当作当前答案。
- 关系只有结论，没有可解释的依据。
- 文档更新后，知识版本和引用没有同步演化。

质量发现应被记录并可追踪。对于非关键场景，可以先提示而不中断知识使用；对于高风险决策，则应按敏感度和用途设置更严格的人工确认要求。

### 8. 保护权限与敏感语境

知识被连接后，原本分散的信息可能产生新的敏感含义。权限不应因为知识被索引、摘要或关联而自动扩大。

- 继承原始来源的访问限制和敏感等级。
- 对个人信息、商业秘密和受限材料保持最小可见范围。
- 检索结果不得通过关系链泄露无权访问的来源。
- 摘要、推断和组合结果也应接受与原始信息相匹配的审查。
- 删除或撤回来源后，应能识别受影响的知识和回答。

### 9. 标准对齐建议

标准对齐用于提高语义清晰度和跨系统可移植性，不意味着必须采用某种具体实现：

- OKF 可作为人和智能助手共同维护的文档表达格式。
- RDF 1.1 可作为知识对象与关系的通用交换模型。
- SKOS 可用于概念、首选名称、别名、层级和关联关系。
- PROV-O 可用于表达来源、生成、修订和派生过程。
- SHACL 可用于描述和验证知识结构的完整性约束。

采用标准词汇时，应只在语义真正一致时复用。使用某个标准术语不等于已经实现该标准的全部推理、验证或查询能力。

### 10. 最小验收清单

一组文档知识可以进入正式使用前，至少检查：

- [ ] 核心概念、主张和证据已经区分。
- [ ] 稳定身份、版本和文档位置没有混用。
- [ ] 关键关系具有明确方向和定义。
- [ ] 重要结论能够回到来源与上下文。
- [ ] 不确定、冲突和失效状态可见。
- [ ] 同名、别名和多版本歧义得到提示。
- [ ] 检索结果能够说明来源、版本和适用边界。
- [ ] 敏感信息的访问范围没有因连接而扩大。
- [ ] 质量问题可以被记录、复查和关闭。
- [ ] 标准对齐声明与实际能力保持一致。

## 典型使用场景

### 研究与学习

围绕一个主题串联定义、观点、证据和参考资料，帮助使用者从“找到资料”进一步走向“理解知识结构”。

### 决策追溯

将决策与背景、依据、约束、反对意见和后续结果关联起来，使团队能够复盘当时为什么这样选择。

### 制度与标准管理

区分现行规则、历史版本、适用范围和例外条件，减少引用过期内容或混用不同口径的风险。

### 内容生产

从已有知识中发现可复用的主题、论据、案例和引用，降低重复整理成本，并保持不同内容之间的一致性。

### 智能问答

为回答提供相关知识及其来源线索，使回答可以说明依据、识别冲突，并在证据不足时表达不确定性。

### 新成员学习

通过概念、流程、决策和经验之间的连接，帮助新成员理解组织知识的整体脉络，而不是孤立阅读大量文档。

## 可信原则

- 来源优先：重要知识应能回到原始文档或明确来源。
- 事实与观点分离：可核验事实、分析判断和个人观点分别表达。
- 版本可追溯：新结论不抹去旧结论形成时的背景。
- 语境不丢失：脱离适用条件的结论不能被当作普遍事实。
- 缺失不等于否定：没有记录的信息，只能说明当前未知。
- 冲突不被隐藏：不同来源的矛盾应保留，等待进一步判断。
- 不确定性可见：推测、待确认和已证实知识应保持不同状态。
- 关系不过度推断：相关不等于因果，相似不等于相同。

## 它不是什么

文档知识图谱不是自动产生真相的工具，也不是把所有文档压缩成唯一结论的方法。它不会消除知识中的分歧，而是让分歧的来源和边界更加清楚；它不会取代完整文档，而是为跨文档理解提供连接；它也不要求所有知识立刻完整，未解决的问题同样可以成为可追踪的知识对象。

## 最终愿景

当文档知识图谱持续积累后，组织获得的不只是更多资料，而是一张能够说明知识含义、来源、关系和演化过程的认知地图。人可以更快找到可信信息，团队可以更有效地复用经验，智能助手也能在更清晰的语境与证据边界内工作，从而减少重复劳动、歧义和无依据推断。
