## 3. 产品定义

### 3.1 一句话定义

GTKG V0.2 是一套本地优先、单 Core、无数据库的知识工程产品：它在冻结的 Coverage Profile 内，把代码和文档的精确源快照转换为 Typed Semantic IR、可验证 Atomic Claims、Google OKF 知识、可查询的文件型 Graph v3、可审计 ContextPack 以及 Wiki/A2UI 投影，使人和 Agent 获得来源可追溯、边界明确、可增量重建和可回放的工程理解。

### 3.2 “全面逆向”的正式定义

V0.2 禁止无边界使用“全面支持所有代码和文档”。唯一允许的完成声明是：

~~~text
comprehensive_for_profile:<profile_id>
~~~

Coverage Profile 必须冻结：

- 文件角色、路径范围和媒体类型；
- 支持的语言、格式和逐能力状态；
- adapter、resolver、tokenizer、prompt 和 verifier identity；
- Graph 关系类型；
- claim/grounding policy；
- current OKF spec version、commit 和 raw SHA-256；
- Context/token budget；
- Benchmark corpus exact-set；
- 安全、规模、性能和质量阈值。

Profile 内必须满足：

~~~text
discovered = admitted + omitted
hidden_omission = 0
eligible_supported_discovered = admitted
~~~

其中 eligible_supported_discovered 仅包含：位于 Profile 范围内、声明为 supported、输入未损坏、未超资源上限且未被权限/数据策略拒绝的对象；它们必须 100% admitted。omission reason 只能来自固定枚举：unsupported_format、unsupported_capability、corrupt_input、needs_ocr、resource_limit、policy_denied、excluded_by_profile。任一 required capability 为 partial、unsupported、failed 或遗漏时，不能声明 comprehensive_for_profile。

每个 required gate 必须 current/passed。任一 required gate 为 failed、blocked、not_run、stale、invalid 或 cannot-confirm 时，状态不能高于 partial。

### 3.3 Canonical V0.2 Release Profile

V0.2 必须内置不可降级的 **GTKG-V0.2-CORE** product-certified profile。用户可以创建 custom profile，但 custom profile 只能声明 comprehensive_for_custom_profile，不能满足 V0.2 GA 或对外声明产品级全面支持。

| 输入类别 | Required formats/languages | GTKG-V0.2-CORE 最低 required capabilities |
|---|---|---|
| 文档 | Markdown | frontmatter、heading、paragraph、list、table、code fence、link、footnote、EvidenceSpan |
| Office/PDF | PDF、DOCX、XLSX、PPTX | 静态文本与结构 locator；page/paragraph/table/sheet/cell/slide；OCR 不属于默认 required capability，扫描件必须 needs_ocr |
| 配置 | JSON、YAML、TOML | syntax tree、object path、key/value/type、reference locator、损坏输入诊断 |
| Web/脚本 | HTML、CSS、SVG、Shell | 静态 syntax/facts、route/component/selector/asset/command locator；目标脚本执行数=0 |
| 代码 | Rust、Python、TypeScript、JavaScript | syntax、symbols、scopes、imports、references、types、inheritance、calls、CFG、exception、def-use、state-flow capability states |

产品 conformance corpus 中每个 required format、language 和 capability 的 gold denominator 必须非空；不能用零样本得到通过。实际项目中某格式没有文件时允许 denominator=0，但只能说明“本项目未发现该格式”，不能用它证明对应产品能力。Profile 缩小、删除困难格式或把 required 改为 optional 必须产生新 profile_id，并使 product-certified claim 不适用。

14. Template、immutable version、Git 三域、Snapshot、Coordinator/Worker 既有能力。

4. 关系、文档、图、向量、搜索、KV 或嵌入式数据库。
5. Core 直接绑定任一 LLM provider SDK。

7. embedding 相似度作为事实证据。
8. 自动代码修复、代码生成或真实生产行为证明。

### 7.3 Structural Graph 与 Knowledge Overlay

Graph v3 分为两个可独立构建和查询的层：

1. **Structural Graph**：由 SourceSnapshotV2、Typed IR 和 resolver 确定性生成，不依赖 LLM、claim 或 provider；无 provider、全部 abstain 或 LLM blocked 时仍可提供 module/symbol/import/call/type/CFG 等结构查询。
2. **Knowledge Overlay**：仅由 accepted OKF claims、sources、footnotes、verification 和 provenance 生成，叠加在 structural graph 上。

QueryReceipt 必须声明 mode=structural_only 或 structural_plus_knowledge。缺 Knowledge Overlay 时不能回答需要自然语言 claim 的问题，但不能阻断纯结构 neighbors/path/impact/explain。

### 7.4 Claim、Narrative 与 Abstention 状态

semantic_assertion_denominator 包含 title、description、正文、列表、表格中所有可验证的陈述句或陈述性 clause。唯一豁免是纯 heading label、格式符号和不表达新事实的连接词。

NarrativePlan 只能决定 accepted claim/abstention 的顺序、分组和展示标题，不能引入任何新事实文本。最终 narrative 必须由 Core deterministic renderer 生成；每个 semantic assertion 必须反向映射唯一 claim_id。

| 状态 | 条件 | 能否计入 grounded/comprehensive numerator |
|---|---|---|
| accepted_grounded | required sections 完成；全部 semantic assertions entailed；无 required abstention | yes |
| accepted_partial_with_abstention | 至少一条 entailed claim；所有缺口以 abstention 显式列出 | grounded numerator=no；可作为 partial artifact |
| no_semantic_claim | 输入没有可合理提炼的语义 claim，且理由可验证 | no；不是失败，但不能刷 summary success |
| rejected | claim-free、unsupported、contradicted、identity/coverage/staleness 不合格 | no |

全部 abstain 只能形成 no_semantic_claim 或 rejected，不能形成 accepted_grounded/accepted_partial。unknown claim 不得 accepted；它只能触发 revise、reject 或明确 abstention。

## 16. Migration、Current 与 Rollback

### 16.1 Migration

1. 冻结 v1 schema、fixture、bundle bytes 和 reader behavior。
2. 新增 v2 operation/readers/writers，不改变 v1 request/response。
3. Shadow 生成 v1/v2，Current 仍指向 v1。
4. 比较 denominator、claim、graph、query、omission 和 projection。
5. Hard Gates 全绿后，v2 只获得“可生成第一个 stable candidate”的资格；v1 仍是默认 write/read。
6. 连续两个 v2 stable version 闭合后，才由用户另行决定是否把 v2 设为默认 write；v1 继续保留 read/verify/query/replay。stable version 定义为：来自两个不同且至少一个包含非平凡 mutation 的 exact source snapshot，所有 V0.2 Development Gates current/passed、P0/P1 findings=0、independent completion audit passed、immutable readback passed。
7. 即使 v2 成为默认 write，至少再保留两个稳定版本窗口后，才可另行评估关闭 v1 write。
8. migration_gap bundle 只允许 Replay。

可迁移：

- source/manifest/receipts；
- schema-compatible 且重新验证通过的 IR。

不可自动迁移：

- v1 自由 Markdown；
- claim-free summary；
- unspecified provider 结果；
- 未闭合 provenance。

### 16.2 Current/Replay

- Current 与 Replay 使用 tagged selector。
- Replay 永不写 Current、canonical state 或外部系统。
- Current query 绑定 caller-held CURRENT digest。
- Old bundle 可 Replay，但不能以旧 resolver/spec Evidence 满足 Current。
- Current activation 继续需要授权、CAS 和 exact readback。

### 16.3 Rollback

触发：

- bundle/manifest/shard/readback failure；
- source/provider/verifier/spec drift；
- Graph Query correctness regression；
- security/privacy escape；
- incremental/full mismatch；
- migration laundering。

行为：

- 停止 activation；
- 保留首败和 suspect bundle；
- 只有“本次 activation 已成功写入且后置 exact readback/验证失败”时，才允许以重新读取到的 Current digest 作为 expected value，执行一次补偿式 CAS 指针回退到上一 verified immutable version；
- 不删除、不覆盖、不原地修复历史；
- suspect bundle 标记 Replay-only/quarantined；
- 不重放已确认的外部写入。

CAS conflict 表示本次 activation 未取得写权限或并发状态已变化：只能 exact readback、reconcile 并返回 blocked/conflict，外部和 Current 写入次数必须为0；不得通过“回滚”覆盖另一个成功 actor 的 Current。

## 17. Security 与数据策略

- Source、Markdown、frontmatter、link、NDJSON 和 LLM 文本一律为 untrusted data。
- 禁止目标 build/run/proc macro/plugin/script 执行。
- 默认拒绝网络、凭证、HOME、SSH、越界写和任意子进程。
- Extractor/resolver/query 默认网络调用数为 0。
- Remote provider 前执行 secret/PII/repository visibility/data-policy Gate。
- Provider 无权读取未选入 ContextPack 的 source。
- Verifier 无工具权限，只接收 atomic claim 和精确证据。
- API key、Cookie、Authorization、原始 CoT 永不写入 artifact/log/output。
- 外部 URI 只建 source node，不自动访问。
- Wiki/A2UI sanitize dangerous URI、HTML、SVG 和 action。
- 不同权限域优先拆分 bundle；索引继承 source visibility。
